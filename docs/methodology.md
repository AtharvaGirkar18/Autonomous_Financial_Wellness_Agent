# Methodology

## 1. Synthetic data generation

A fixed random seed (`42`) generates 18 synthetic Indian user profiles over six months. The transaction generator includes salary deposits, rent, EMI, utilities, UPI transactions, card subscriptions, variable discretionary spending, five ground-truth anomalies per user and two ground-truth duplicate pairs per user. No real banking or personal financial data is used.

The generated dataset currently contains **3,294 transactions**, **18 users**, **6 months**, **90 labeled anomalies**, **72 labeled duplicate rows**, and **54 recurring subscription merchant records** (324 subscription transaction rows).

## 2. Ingestion

CSV files are normalized with pandas. PDF statements generated by the same synthetic data use line-oriented pipe-separated records and are extracted with PyMuPDF. Dates and amounts are converted to consistent types, transaction signs are normalized through the `transaction_type` field, and duplicate transaction IDs are removed.

## 3. Categorization

Three approaches are evaluated: a merchant-rule baseline, TF-IDF + Logistic Regression, and a hybrid model. The hybrid uses high-confidence merchant rules first and the ML classifier for ambiguous rows. When user-uploaded data has no category labels, the implementation can use the synthetic reference dataset as a training source for demonstration purposes.

## 4. Spending and budget analysis

Monthly income/expense totals, category totals, essential vs discretionary spending, trends and savings rate are deterministic pandas calculations. Budget utilization is computed for the latest observed month and uses user-editable category limits.

## 5. Financial health

The score is deterministic and weighted across savings rate, expense-to-income health, debt health, budget discipline, emergency-fund coverage, spending consistency, recurring-debit burden and cash-flow stability. The LLM is not allowed to invent or directly calculate the score.

## 6. Anomaly and duplicate detection

Anomaly detection combines an Isolation Forest model with an interpretable local-spend rule that compares non-recurring transactions to user/category baselines. Duplicate candidates use a deterministic same-user, same-date, same-merchant, same-amount rule. Duplicate metrics are reported separately from anomaly metrics.

## 7. Subscription intelligence

The detector requires a known subscription merchant, a subscription category/label, or an explicit subscription flag before classifying a recurring charge as a subscription. Actual usage evidence is not inferred from financial data; the UI therefore uses the wording **potentially unused** rather than claiming a subscription is definitely unused.

## 8. Cash-flow forecasting

The forecast uses the current balance, recent non-recurring daily net flow and a learned schedule of recurring monthly flows. It returns a daily 30-day projection and an uncertainty interval based on recent flow volatility. Separate monthly forecasting experiments compare a naive last-value forecast with a three-month moving-average forecast.

## 9. Planner and reviewer

The planner first tries an LLM-based intent/plan output, then sanitizes the result against a closed agent allow-list. When the LLM is unavailable, a deterministic keyword planner selects an appropriate route. The reviewer validates that all required state outputs exist and that recommendations contain evidence metadata; unsupported recommendations are removed as a repair action.

## 10. Proactive monitoring and memory

A data ingestion event triggers the complete monitoring cycle in demo mode. Alerts are created for budget risk, anomalies and projected low balances. SQLite persists financial state and observability so later workflow runs can retrieve recommendation history.

## 11. Reproducibility

Dataset creation and ML models use fixed random seeds. Evaluation artifacts are generated by:

```bash
python data_generation/generate_dataset.py
python -m ml.evaluation --csv data/synthetic_transactions.csv --output-dir artifacts/evaluation
pytest -q
```

## Limitations

The dataset is intentionally synthetic and separable; measured metrics should not be generalized to real financial institutions. The cash-flow model is a lightweight demonstration model, not a banking-grade liquidity engine. The application does not use actual card/UPI usage telemetry, so subscription “unused” status remains only a candidate for review. LLM output is optional and is kept outside deterministic financial arithmetic.
